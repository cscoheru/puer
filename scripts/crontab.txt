# puer.im 生产 crontab —— **正本**
#
# 为什么这个文件存在（R27 的教训）：
# 服务器的 crontab 只存在于服务器上（`crontab -l`），仓库里没有任何文件
# 记录它 —— 于是「新增一个定时任务」这件事只活在服务器里，下次换机/重建/
# 手工同步时就会**静默消失**，而且没人发现（cron 只是少跑一个任务而已）。
#
# 所以：**改 crontab 必须改这个文件**，然后同步到服务器，两边都要有。
#
# 装到服务器上：
#   crontab -l > /tmp/crontab.current          # 先备份
#   （把下面生效的行加进去）
#   crontab /tmp/crontab.new
#   crontab -l | diff - scripts/crontab.txt    # 核对
#
# 时间一律 **UTC**（服务器 TZ=Etc/UTC）。北京时间 = UTC + 8。
#
# 任务清单与 scripts/cron-task.sh 的分支一一对应。

# ── 备份与健康检查 ────────────────────────────────────────────────────────

# 每日数据库备份（保留 7 天）
0 4 * * * mkdir -p /opt/puer-hub/backups/db && cd /opt/puer-hub && docker compose exec -T postgres pg_dump -U puerhub puerhub | gzip > /opt/puer-hub/backups/db/$(date +\%Y\%m\%d).sql.gz && find /opt/puer-hub/backups/db/ -mtime +7 -delete

# 每 5 分钟探一次站点，挂了写告警
*/5 * * * * curl -sSf -o /dev/null https://puer.im/forum 2>&1 || echo "[ALERT] Site down at $(date)" >> /opt/puer-hub/backups/health-alerts.log

# 每日 uploads 备份（保留 7 天）
17 3 * * * tar czf /opt/puer-hub/backups/uploads-$(date +\%Y\%m\%d).tar.gz -C /opt/puer-hub uploads/ && find /opt/puer-hub/backups/ -name "uploads-*.tar.gz" -mtime +7 -delete

# 备机镜像同步（每 6 小时）
0 */6 * * * /opt/puer-hub/scripts/sync-images-to-standby.sh >> /opt/puer-hub/backups/image-sync.log 2>&1
