## 1. 背景与目标

puer.im 已有茶品库（1729 款，其中 195 款经典）、品鉴笔记、论坛、互换大厅、茶问。核心资产是站长长期、口味一致的第一手品鉴记录，以及按时间排开的转化档案。陈年茶的价值来自时间序列，而时间序列无法事后补采，越早让用户开始记录，资产累积得越早。

目标（按优先级）：

1. 把现有笔记和后续用户记录沉淀为可对比、可画曲线的结构化数据。
2. 用“我的茶仓”工具让用户持续、低成本地记录，成为数据的持续来源。
3. 借鉴烂番茄的“分层展示、不平均”机制建立可信度。
4. 防止图片和真实品鉴内容被批量抓取和滥用。
5. 为日后付费做好权限底座，但本期不上线付费墙。

## 2. 产品原则

1. 正文公开引流，衍生层才是资产：公开品鉴正文不上锁；曲线、社区带、校准、高清图、导出属于衍生层。
2. 自洽优于严谨：相对变化比绝对分可靠；仓储、器具不求精确，但每条曲线必须声明数据来源与口径。
3. 永不平均：站长、社区、个人三条线分开呈现，任何地方不得合成一个总分。
4. 用户数据默认私有；参与匿名汇总需明确同意，可随时撤回、导出、删除。
5. 数据层只来自真人一手记录：站长线、社区带只能由站长原始笔记和用户自己的记录构成；AI 整理的文章是衍生内容，必须标注，且永不回流进数据层。

## 3. 烂番茄对标（取其机制，不取其形式）

- 影评人分与观众分并列、不合并 → 站长线与社区带并列，另有“我的线”。
- Verified 观众（真实购票）→ “真实回访”：对同一条茶仓记录间隔 ≥30 天品鉴 ≥2 次，才计入社区带。
- Top Critics → “认证品鉴人”：以后可开放多位站长级作者，本期只有 role=editor 的站长本人。
- 展示样本量 → 社区带显示样本数，不足阈值时不显示数值。
- 两边评价分歧 → “分歧提示”，只提示，不裁决。
- 不取：全站总榜、百分比新鲜度、综合总分。

## 4. 术语

- 站长线：role=editor 作者对某款茶的品鉴时间序列，只含真人撰写的内容（source=editor）。
- 社区带：用户授权汇总后的分布（中位数 + 四分位区间），按储仓评分的最近锚点分组。
- 我的线：用户自己的私有时间序列。
- 茶仓条目（CellarItem）：用户持有的某款茶及其仓储环境。
- 回访：对同一茶仓条目的再次品鉴。

* 原始笔记：站长亲自品鉴后写下的笔记，是数据层的唯一来源。
* AI 整理文章：AI 基于原始笔记生成、经人工审核后发布的帖子，属于衍生内容，不进入数据层。
* 全自动 AI 文章：AI 自行检索、选题、创作的帖子（趋势、行情类，尚未上线），不基于站长一手记录。
* 储仓评分：对存放环境干湿程度的 45–60 评分（见第 6 节）。

## 5. Roadmap

**Phase 0 · 底座与防护快赢（先做）**

- 现状审计；feature flag；权限骨架（free / member）。
- 数据模型迁移（第 6 节）；给现有内容标注来源，并落实 F0 的署名与标注规则。
- 反滥用快赢：robots 策略、限速、图片公开版降分辨率加水印、原图私有化（第 8 节）。
- 退出标准：审计被站长确认；迁移上线无回归；图片水印生效。

**Phase 1 · 回填与站长线**

- LLM 回填现有站长笔记的结构化字段（F1）。
- 茶品页展示站长线曲线与来源声明，先覆盖 195 款经典。
- 退出标准：抽检一致率达标；195 款经典页均有站长线或显示“暂无记录”。

**Phase 2 · 我的茶仓 MVP**

- 茶仓、仓储登记、三下点击快速品鉴、私有默认、导出与删除（F2）。
- 条目页展示站长线对照。
- 退出标准：站长与至少 10 位种子用户内测一周，快速品鉴的中位耗时 <30 秒。

**Phase 3 · 社区带与双线（F3）**

- 汇总授权、真实回访、社区带、分歧提示。
- 退出标准：至少 10 款茶达到样本阈值并出带，且无单人主导。

**Phase 4 · 复饮提醒与行情联动（F4、F5）**

- 提醒；行情手工录入后台；茶品页价格区间与站长线叠加。

**Phase 5 · 会员与口味校准（门槛触发）**

- 仅当第 9 节的启动门槛达成才开始（F6、F7）。

## 6. 数据模型

以下为概念模型，字段名与表结构以现有代码库为准，阶段 0 审计后对齐。

```
Tea（现有）       保持现有字段，经典标记沿用现有字段

Tasting（数据层）  source: editor_note | user_log | imported    # 禁止由 AI 文章生成；站长线只取 editor_note
                  + visibility: public | private
                  + cellar_item_id?
                  + tasted_at: date
                  + delta_vs_prev?: better | same | worse
                  + stage?: young | transforming | peak | declining
                  + dims?: {aroma 香气, flavor 滋味, water_path 水路, body_feel 体感}   # 生熟统一四维，每维 1–10 分
                  + descriptors?: {dim: [tag]}    # 描述词库按生熟与年份段分层
                  + overall_legacy?               # 保留现有综合评分
                  + grams?, vessel?
                  + extraction_meta?: {model, prompt_version, confidence, human_reviewed}

CellarItem        id, user_id, tea_id, acquired_at?, qty_note?,
                  remind_every_months (default 6), next_remind_at?

StorageEpoch      cellar_item_id, starts_at, storage_score (45–60), assessed_by: self | editor, city?, container?
                  # 45 标准偏干（最干）· 50 标准仓 · 55 标准偏湿 · 60 湿仓
                  legacy_storage_label?    # 互换大厅原有分类，仅用于展示

DescriptorVocab   category (raw | ripe), age_bracket, dim, tag    # 词库由站长提供

Post（论坛帖）     origin: human | ai_from_notes | ai_autonomous
                  + source_note_ids[]      # ai_from_notes 必填
                  + reviewed_by?, reviewed_at?
                  + disclosure_label       # 前台展示的来源标注
                  + posted_as_account_id   # 统一署名账号

PriceSnapshot     tea_id, snapshot_date, low, high, currency, source_label, entered_by, note

User（增补）       share_aggregate: bool (default false), share_consented_at?,
                  role: user | editor | admin | system, is_synthetic: bool, plan: free | member
```

四个维度的评分锚点文案（每档一句描述）、储仓评分的锚点描述和描述词库均由站长提供，CC 先放占位文案，并在 PR 中标出。

**储仓评分（storage\_score）**

- 范围 45–60：45 标准偏干（最干）、50 标准仓（不干不湿）、55 标准偏湿、60 湿仓。采用黄刚先生提出的“标准偏干”概念；不采用港式“纯干仓、干仓、自然仓、港仓”四分法，站长判断它更适合 90 年代前的老茶，不贴合当前普洱的实际存放。
- 录入界面只显示 45/50/55/60 四个锚点及各自的描述，允许选中间值。用户评分标注为“自评”，站长对自己茶仓的评分标注为“站长评”。
- 站长对自己的茶仓一次性手工评分，不由 LLM 从笔记中推断。
- 社区带按最近的锚点分四组，每组各自满足样本阈值。

**四维评分**

- 生普、熟普和不同年份统一使用香气、滋味、水路、体感四个维度，分值可跨茶比较。
- 差异只在描述用词：DescriptorVocab 按生熟和年份段提供标签，记录时点选，不影响分值口径。

## 7. 功能需求

**F0 内容来源与发布管线治理（Phase 0，先于任何新功能）**

- 站内内容分三层，数据与前台都必须可区分：原始笔记；AI 整理文章（基于站长笔记，经人工审核）；全自动 AI 文章（AI 自行检索、选题、创作，尚未上线）。每篇帖子记录 origin、来源笔记 ID、审核人与审核时间。
- 前台统一标注：AI 整理文章显示“站长笔记 · AI 整理”；全自动文章显示“AI 生成 · 非站长品鉴”，并附信息来源链接。统一用一个署名账号发布，不使用多个账号扮演不同的真人。
- 单向流动：AI 文章不得成为 Tasting 数据、站长线、社区带的来源，不得被 F1 抽取；茶问检索时需能区分 AI 文章并标注来源。
- 保留现有“草稿 → 审核 → 归档 → 发布”流程。审核页并排展示来源笔记原文；价格、年份、产地、仓储等事实性陈述需逐项勾选核对。定时发布设每日上限和一键暂停开关。
- 全自动 AI 文章（趋势、行情类）在上述规则落实前不上线；上线后所有数字必须来自 PriceSnapshot 或带链接的可查证来源，不得由模型自行给出，且与品鉴内容分板块展示。
- 长期方向：选题优先取自站内结构化数据（如“本月有 N 款茶进入适饮期”“某款茶两年的价格区间与转化对照”），而不是通用网页检索。

* 自动化账号：凡由系统控制的账号（含现有的“随机活跃账号”）一律标记 is\_synthetic=true，不得以真人身份出现；其发帖、投票、回复、浏览不计入 DAU、留存、社区带、真实回访，也不计入任何对外展示的计数。
* 现有定时的投票与回复任务：默认用 feature flag 关闭，在上线“我的茶仓”与社区带之前完成。自动投票一律停止；自动回复和发帖只允许使用带“AI”标注的账号。历史自动化投票保留记录用于审计，但不再计入前台展示的计数。
* 指标重算：Phase 0 内重算近 90 天的 DAU、留存和互动数据，剔除自动化账号和爬虫流量，作为新的基线。

**F1 回填（Phase 1）**

- 仅对站长原始笔记（不含任何 AI 整理文章）批量抽取 stage、delta\_vs\_prev、dims、descriptors、grams、vessel。原文未提及的字段保持为空，禁止推测补全。储仓评分不由 LLM 推断，由站长对自己的茶仓一次性手工评分。
- 抽取结果写入 extraction\_meta；低置信度进入人工复核队列；原文不可变。
- 先由站长手工标注 50–100 条作为评测集，抽取一致率达到站长设定的阈值（建议 stage、delta 不低于 85%）后才允许批量写入。
- 有成本上限与重试，可 dry-run，可按批次回滚。

**F2 我的茶仓（Phase 2）**

- 添加茶：搜索茶品库（经典优先）；找不到可自建，进入待审核队列，由站长并入茶品库。
- 仓储登记：储仓评分（45/50/55/60 四个锚点，可选中间值，标注为自评）+ 城市 + 容器，三项都可跳过；换仓时新增一条 StorageEpoch。
- 快速品鉴，目标三下点击完成：①比上次（更好 / 差不多 / 更差）②状态阶段 ③保存。可选项：四维评分（香气、滋味、水路、体感）与描述词点选、备注、图片、投茶量、器具（默认沿用上次）。首次品鉴不显示“比上次”。
- 默认私有；可导出 JSON / CSV；可一键删除全部数据。
- 条目页展示站长线对照（该茶有站长线时）。这是用户不依赖任何社区数据就能得到的第一份价值。

**F3 双线评分与曲线（Phase 3，对标烂番茄）**

- 茶品页头部并列三块：站长 / 社区 / 我的（未登录不显示“我的”）。
- 站长线：时间轴上的 stage 与评分，标注当时的仓储；图下自动生成来源声明，例如“站长线：一人 · 一个家庭仓 · 器具不固定”。
- 社区带：只汇总 share\_aggregate=true 且达到“真实回访”的用户；按储仓评分的最近锚点（45/50/55/60）分四组，显示中位数和四分位区间。每组需 ≥5 位不同用户，否则显示“样本不足（已有 x/5 位）”，不显示数值。
- 防操纵：每用户每款茶每月最多 1 点计入；注册不足 14 天的账号不计入；任一分组中单个用户占比不得超过 30%；与自身历史严重偏离的异常点打标复核。
- 分歧提示：同一时间段站长与社区中位数差距超过阈值时，提示“站长与社区看法不同”，不判断谁对。
- 社区带与完整曲线仅登录用户可见（衍生层）。

**F4 复饮提醒（Phase 4）**

- 每条茶仓条目默认每 6 个月提醒复饮，可调；最近一次为“更好”时建议缩短间隔，为“走下坡”时建议尽快喝。
- 渠道：站内通知 + 邮件月度汇总；不做高频推送。

**F5 行情联动（Phase 4）**

- 管理后台手工录入 PriceSnapshot：只录区间不录点值，必须填来源与日期。范围为 195 款经典，加上出现在任一用户茶仓里的茶；频率按季度。
- 茶品页：价格区间时间线与站长线叠加，可对照“价格涨跌”与“转化状态”。
- 全站声明：行情仅供参考，不构成投资建议。不做茶仓估值。

**F6 口味校准（Phase 5，门槛触发）**

- 用户与站长重叠品鉴 ≥8 款后，计算个人相对站长的偏差，显示“按你的口味校准”的参考，并说明算法与样本数。

**F7 会员与权限（骨架在 Phase 0，付费在 Phase 5）**

- 先做权限骨架与功能开关：hd\_images、curves\_full、community\_band、reminders\_advanced、calibration、export。
- 定价与支付通道待定，本期不实现。

## 8. 反滥用与内容保护（Phase 0 起贯穿）

- 图片：公开展示版降到长边不超过 1080px，并平铺淡水印（含站点标识）；原图私有存储，仅会员通过短期签名 URL 获取；移除 EXIF；防盗链。会员高清图可叠加用户名水印，用于追溯泄露。
- 抓取：按 IP 与账号限速；列表翻页深度设上限；检测批量遍历行为并临时封禁；不提供公开的批量接口；记录并告警。
- AI 爬虫：在 robots.txt 与响应头中声明策略。默认建议屏蔽训练类爬虫（如 GPTBot、ClaudeBot、CCBot、Google-Extended，名单以各家官方最新文档为准），搜索与引用类爬虫是否放行由站长决定（见第 11 节）。声明无法强制执行，必须配合限速。
- 条款：更新用户协议，包含用户授予站点的使用授权、禁止抓取与用于模型训练、站长原创笔记的版权声明。CC 只出草稿，由站长自行请法律人士审阅。
- 衍生层（曲线、社区带、校准、导出）仅登录可见：既对应日后的付费分层，也让批量采集更难。

## 9. 指标与门槛

- 激活：新用户 7 天内登记 ≥1 条茶仓并记录 ≥1 条品鉴。
- 核心：每月“回访品鉴”数；提醒点击到记录的转化率。
- 资产：时间跨度 ≥2 年的茶品数；达到社区带阈值的茶品数。
- 防护：被拦截的异常抓取次数。以上所有指标只统计真实用户，剔除自动化账号和爬虫。
- 启动付费（Phase 5）的建议门槛，站长可按实际调整：≥50 位活跃茶仓用户，其中 ≥30% 在 90 天内有过回访品鉴；出带的茶 ≥20 款。

## 10. 明确不做

全站排行榜；综合总分；茶仓估值与投资建议；扩展到其他茶类；关注、私信等社交功能；重做论坛；云喝茶改造（暂搁置）；锁住公开的品鉴正文；在 F0 规则落实前上线全自动 AI 趋势与行情文章。

## 11. 待确认事项（含默认假设）

1. 现有评分的口径是什么？默认：现有综合评分保留为 overall\_legacy，不参与新曲线。
2. 现有“行情快照”的来源与授权？默认：不新增抓取，沿用现状；新增数据全部手工录入。
3. 已确认：现有帖子均为 AI 基于站长笔记生成、经人工审核后发布。处理：帖子 origin 统一标为 ai\_from\_notes，不进入数据层；站长线只取原始笔记。
4. 已确认：目前没有付费用户，无需迁移，会员层可从零设计。
