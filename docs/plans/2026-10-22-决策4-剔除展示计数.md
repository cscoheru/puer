## 三、改了什么

**展示层**（`src/lib/real-content.ts` 统一口径）

- 详情页：回复/点赞按作者过滤；「阅读」改用 `article_views` 的**去重真实读者数**
- JSON-LD 的 `interactionStatistic` 同步换成真实计数 —— 把爬虫灌出来的互动量
  喂给 Google 判断讨论页活跃度，本身就是 cloaking
- 评论列表 API 过滤机器人评论（**只隐藏不删**，PRD 说历史记录保留用于审计）
- 用户主页的获赞/阅读同样按真实口径
- 繁体页同步

**计数列重算**（`scripts/recompute-real-counts.mjs`）

- 幂等（按实际明细重算，不做自增自减）、dry-run 默认
- 写库前存改前快照：`/opt/puer-hub/backups/real-counts-before-20261022T013837.json`
- 共重算 488 行（481 帖 + 7 版块）→ 修正判定规则后重跑，最终 4,425 / 388

## 四、`viewCount` 为什么不重算

`articles.viewCount` 是 SSR 页面**每渲染一次 +1** 的计数器，**没有作者维度**
——爬虫的每次渲染都计入，无法按账号拆分。

它的定位是**热度**（`admin/hot` 的热榜公式用它的相对值），不是「多少人读过」。
前台展示的「阅读」已改用 `article_views` 的去重真实读者数。

⚠️ **过渡期现象**：`article_views` 是 2026-10-22 才建好的表，目前几乎没数据，
所以详情页会显示「暂无读者记录」。这是**真实状态**，不是故障 —— 跑几天后自然
有数。如果不想要这个过渡期，可以把展示改回 `viewCount` 并改名为「浏览次数」，
但那样就把爬虫数据又端上来了。

## 五、还没做的

- **admin 概览保持全量**（有意为之）：站长需要看到机器人在干什么，那是运维
  视角，不是用户视角。用户侧的展示（详情页、列表、评论、主页）已经全部换成
  真实口径。
- **热榜公式未调**：仍用 `viewCount`（含爬虫）。等 `article_views` 积累起
  可用数据后，可以把热度公式换成真实读者数。

  只能从 nginx 日志估算（保留约一天）。

## 七、判定规则事故（2026-10-22 修正）

这份报告的初版把「真实用户」写成 **5 个**，DAU 写成 2.5。**那是错的**，
错因是一次判定规则事故，站长当场质疑「我知道的就有七八位茶友注册了」
才查出来的。

### 错在哪

2026-10-21 标记合成账号时用的是**邮箱域名**规则（`uidN@puer.local` /
`@puer.tea` / `@mock.local`）。但注册接口**自动生成邮箱**：

```ts
// src/app/api/auth/register/route.ts
email: `uid${nextUid}@puer.local`,
```

**真人和 auto-register 造出来的机器号用的是同一个域名格式** —— 域名根本
区分不了谁是谁。于是 70 个真人注册账号被误标成合成账号（显晟茶居、温广源、
半盏浓、红嘴山鸦、feifeiyu、dora777、Tommy1979…），他们的赞与评论被从展示
计数里剔掉了。

### 正确判据（三条并用）

| 判据 | 依据 | 单独用会漏什么 |
|---|---|---|
| 有 `registrationIp` | 真人注册接口会写，auto-register 不写 | 2026-05-24 之前注册的（接口那时还没这字段） |
| `nickname ≠ username` | 注册接口会写 nickname（自填昵称才有差异），auto-register 根本不写该字段 | 早期种子脚本也写了 nickname（但等于 username） |
| 邮箱在种子域里 | 机器号用 `@puer.local`/`@puer.tea`/`@mock.local` | 真实个人邮箱域是真人 |

**绝对不碰的两个**：`role=admin`（古道茶人、云水禅心 —— 站长自己的账号，
邮箱落在种子域但无 registrationIp）、`puer-news@puer.local`（系统控制的
AI 发布账号）。

### 修正结果

| | 误报版本 | 修正后 |
|---|---|---|
| 真人账号 | 5 | **68** |
| 机器账号 | 257 | 194 |
| 真人 DAU（平均） | 2.5 | **21.1** |
| 展示计数里的赞 | 723 | **4,617** |
| 展示计数里的回复 | 140 | **423** |

另有站长的两条显式指派（优先于任何自动判据）：
- **9 个压测账号**（uid 1246–1254）→ 统一标注为**合成**（它们不是真实读者）
- **黑马(1073) / 俗尘满腹(1074)** → 标注为**真人**（一开始是批量注册，
  后送给真实茶友；密码是个性化设的）

**教训**：判定「谁是人」不能靠单一弱特征。域名是被系统自动生成的，昵称和
注册 IP 也只在部分时期有效 —— 三条并用 + 显式排除，才够稳。
