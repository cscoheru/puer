# 热榜算法设计文档

> 版本 3.0 — 2026年5月24日

---

## 设计目标

1. **质量优先** — 有实质互动的内容留在热榜，不被时间埋没
2. **机会均等** — 分数相近的帖子，不同用户看到不同排序
3. **新帖机会** — 新发布的优质帖子能快速被发现
4. **冷门突围** — 从未进入前十的帖子有随机机会被推上来
5. **已读降权** — 用户看过的帖子自动排到后面，鼓励探索新内容
6. **作者多样性** — 同一个人最多 3 篇帖子同时出现在热榜

---

## 当前算法（v3.0）

### 核心公式

```
hotScore = contentQuality × mediaBonus × timeBonus × userJitter
```

**不再使用除法衰减** — 好内容不会因为"老了"就被踢出热榜。时间只作为正向加成，不作为惩罚。

### 各因子计算

#### 1. 内容质量 (contentQuality)

```typescript
contentQuality = Math.log1p(netVotes) * 6 + Math.log1p(replies) * 4 + Math.log1p(Math.min(views, 1000)) * 0.2
```

| 因子 | 权重 | 说明 |
|------|------|------|
| 净投票数 (upvotes - downvotes) | ×6 | 对数计算，第1票和100票差异缩小 |
| 回复数 | ×4 | 有讨论的帖子更有价值 |
| 浏览数 | ×0.2 | 上限 1000，避免老帖凭借浏览量碾压 |

#### 2. 媒体加成 (mediaBonus)

```
mediaBonus = 1.3  (有图片或视频)
mediaBonus = 1.0  (纯文字)
```

从早期的 2.5x 降至 1.3x，防止有图帖子长期霸榜。

#### 3. 时间加成 (timeBonus)

```
timeBonus = 1 + 0.3 / (1 + ageHours / 48)
```

| 帖龄 | 加成 |
|------|------|
| 刚发布 | 30% |
| 24 小时 | 20% |
| 72 小时 | 12% |
| 7 天 | 6% |
| 30 天 | 3% |

越新的帖子加成越高，但老帖不会被"惩罚"。

#### 4. 用户个性化抖动 (userJitter)

```
seed = hash(userId + date)       // 登录用户：每人一个种子
jitter = 1 + hash(postId + seed) % 41 / 100  // ±0-40%
```

- 登录用户每人看到不同的热榜排序
- 种子每天变化，同一个人今天明天看到的不同
- 前 5 名抖动幅度 ±0-40%（谁排第一因人而异）
- 中间 10 名 ±0-24%
- 后面 ±0-12%

#### 5. 冷门突围机制

```
每轮从第 15-50 名中随机抽取 2 篇
将其分数提升到接近第 10 名的水平
每用户抽到的不同（确定性随机）
```

确保从未进入前十的好帖子有机会被看到。

## 历史版本

### v1.0（初始版）

```typescript
hotScore = (netScore × mediaBoost × followerBoost) / Math.pow(age + 2, 1.5)
```

问题：媒体帖 2.5x 加成过高，老帖衰减太快，少数帖子长期霸榜。

### v2.0（对数+多样化）

```typescript
hotScore = (logEngagement × mediaBoost × freshness × jitter) / Math.pow(age + 2, 1.3)
```

引入对数评分和机会抖动，但新鲜度加成过大导致刚发布的帖子即便没有互动也能冲顶。

### v3.0（当前 — 质量优先+个性化）

核心思路转变：**不衰减，只加成**。好内容留下，新内容微调，用户个性化决定排序。

## 前端已读追踪

- `localStorage` 存储已读帖子 ID（上限 200 条）
- IntersectionObserver 在帖子滚入视口时自动标记
- 未读帖子排在前，已读排在后，页面上显示绿色「新」徽章
- 下次刷新时，上次看过的帖子自动降权

---

## 后续优化方向

1. **客户端持久化** — 用 IndexedDB 替代 localStorage，支持更多已读记录
2. **互动权重学习** — 根据用户对不同帖子的停留时间、点击行为调整权重
3. **实时热榜** — WebSocket 推送热榜变化，无需刷新页面
4. **A/B 测试** — 不同用户使用不同版本算法，数据驱动迭代
